CENTOS

Introduction to CentOS
CentOS (Community Enterprise Operating System) is a free, open-source Linux operating system mainly used for:
- Web Servers
- Database Servers
- Application Servers
- Cloud Computing
- Enterprise Environments

It is based on Red Hat Enterprise Linux (RHEL) and is known for its stability, security, and performance.

Advantages of CentOS:
- Free and Open Source
- Highly Secure
- Stable Operating System
- Suitable for Enterprise Applications
- Supports Multi-user Environment

Disk Partitioning

Partitioning means dividing a hard disk into different sections so that the operating system and user data can be managed efficiently.

Reasons for partitioning:
- Better data organization
- Easy backup
- Improved performance
- Easier recovery if OS crashes

/boot
Purpose: Stores boot files required to start Linux.
Recommended Size: 2 GB
Contents:
- Linux Kernel
- Boot Loader (GRUB)

Swap Partition
Purpose: Acts as Virtual RAM when physical RAM becomes full.
Rule:
Swap Size = 2 × RAM

Examples:
- 4 GB RAM -> 8 GB Swap
- 8 GB RAM -> 16 GB Swap

/home
Purpose: Stores user files.
Examples:
- Documents
- Downloads
- Videos
- Recordings
- Desktop Files
Recommended: 10 GB or more depending on usage.

Root Partition (/)
Purpose: Stores:
- Linux Operating System
- Installed Software
- System Files
- Configuration Files
Recommended Size: Minimum 150 GB (for 1 TB HDD)

Final Partition Layout:
- /boot | 2 GB | Boot Files
- Swap | 2 × RAM | Virtual Memory
- /home | 10 GB or more | User Data
- / | 150 GB or more | Operating System

Firewall Configuration

A Firewall is a security system that controls incoming and outgoing network traffic. It blocks unauthorized users from accessing your server.

Stop Firewall:
sudo systemctl stop firewalld

Explanation:
- Stops firewall immediately.
- Firewall starts again after reboot.

Disable Firewall:
sudo systemctl disable firewalld

Explanation:
- Prevents firewall from starting automatically during boot.

Quick revision note from the training material:
- Configure or disable FirewallD based on organizational requirements.

SELinux Configuration

SELinux (Security Enhanced Linux) is an advanced Linux security feature. It restricts programs from accessing files or resources without permission.

SELinux modes:
- Enforcing: Security rules are applied.
- Permissive: Violations are logged but not blocked.
- Disabled: SELinux is completely turned off.

Disable SELinux Permanently:
1. Open configuration file:
sudo vi /etc/selinux/config
2. Modify:
SELINUX=disabled
3. Save the file.
4. Restart the system:
sudo reboot

Quick revision note from the training material:
- Configure SELinux as required.
- Enforcing is recommended for production unless specific applications require otherwise.

Important Linux Terminology

Linux:
An open-source operating system widely used for servers, cloud computing, and enterprise applications.

CentOS:
A Linux distribution based on Red Hat Enterprise Linux (RHEL).

Kernel:
The core of the operating system that manages hardware resources and communication between software and hardware.

Booting:
The process of starting a computer and loading the operating system into memory.

Boot Loader:
A program such as GRUB that loads the operating system during startup.

Partition:
A logical division of a hard disk used to organize data and the operating system.

LVM (Logical Volume Manager):
A storage management system that allows flexible resizing and management of disk partitions.
Advantages:
- Easy disk expansion
- Easier backups
- Better storage management

Root User:
The superuser (administrator) with full permissions to manage the Linux system.

Root Directory (/):
The top-level directory that contains all system files and folders.

Home Directory (/home):
Stores personal files and directories for each user.

Swap Memory:
Disk space used as virtual memory when physical RAM is exhausted.

GUI (Graphical User Interface):
Allows interaction with the operating system using windows, icons, and a mouse.

CLI (Command Line Interface):
Allows users to interact with the operating system by typing commands in a terminal.

Terminal:
An application used to execute Linux commands.

Service:
A background process that provides specific system functionality.
Examples:
- NetworkManager
- Firewalld
- SSH

Firewall:
A security feature that filters network traffic based on defined rules.

Firewalld:
The Linux service responsible for managing firewall rules.

SELinux:
A security module that enforces mandatory access controls to enhance system security.

NetworkManager:
A service that manages wired, wireless, and VPN network connections.

IP Address:
A unique numerical identifier assigned to each device on a network.
Example:
192.168.1.20

Subnet Mask:
Defines which part of an IP address identifies the network and which part identifies the host.
Example:
255.255.255.0

Gateway:
The router or device through which the system communicates with other networks or the internet.
Example:
192.168.1.1

DNS (Domain Name System):
Translates domain names into IP addresses.
Example:
www.google.com
->
142.250.xxx.xxx

sudo:
Temporarily grants administrator privileges to execute a command.
Example:
sudo reboot

systemctl:
A command-line utility used to manage Linux services.

Common systemctl commands:

- Starts a service.

systemctl stop service
- Stops a service.

systemctl restart service
- Restarts a service.

systemctl status service
- Displays service status.

- Starts a service automatically during boot.

systemctl disable service
- Prevents automatic startup.

Common operations:

ASTERISK

Asterisk and Telephony Terminology

Asterisk:
A free, open-source PBX (Private Branch Exchange) software that manages phone calls, voicemail, conference calls, and more. It acts as the telephony server that handles SIP/PJSIP calls. The CTI application connects to Asterisk to manage agent calls.

CentOS:
A free Linux operating system where Asterisk is installed.

RPM:
A software package format for Linux, similar to an .exe installer for Windows.

WinSCP:
A Windows tool to transfer files to/from a Linux server over the network.

PuTTY:
A Windows tool used to type commands into a Linux server remotely.

SIP (Session Initiation Protocol):
A signaling protocol used for initiating, maintaining, and terminating real-time communication sessions such as voice calls, video calls, and messaging. SIP peers such as phones and trunks register with Asterisk.

PJSIP:
A newer, more feature-rich SIP library/channel driver in Asterisk that replaces the older chan_sip. It supports features such as WebRTC, IPv6, and better TLS handling.

Trunk:
The connection between the Asterisk server and the phone network.

Dialplan:
The set of rules that determines what Asterisk does when a call comes in or goes out, including routing calls to agents, queues, voicemail, and IVRs.

ACD / ACD Port:
ACD means Automatic Call Distributor / Automatic Call Distribution. It routes incoming calls to the right agent or queue. The ACD Port is the configuration point in the CTI web console that tells the system which Asterisk server to connect to for call routing.

IVR:
Interactive Voice Response, such as a "Press 1 for Sales, Press 2 for Support" menu.

CLI:
Command Line Interface, the text-based interface where commands are entered.

Codec (alaw):
The format used to encode voice audio. alaw is commonly used in India/Europe.

DTMF:
Dual-Tone Multi-Frequency, the tones generated when phone number keys are pressed.

NAT:
Network Address Translation, used when calls pass through routers/firewalls.

CDR:
Call Detail Records, logs of calls including who called, when, and duration.

Httpd:
Apache web server, used here to make call recordings accessible through a browser.

CTI (Computer Telephony Integration):
Technology that allows computers and telephone systems to interact. Interdialog connects to Asterisk to control and supervise calls. CTI can link Asterisk call events with an agent's computer screen for functions such as screen pop-ups and call logging.

AMI (Asterisk Manager Interface):
A management protocol/interface that allows external applications to communicate with Asterisk to control calls, monitor events, and manage the PBX programmatically. The CTI application uses AMI through manager.conf to authenticate and receive real-time call events.

Configuring Asterisk with SIP

Use SIP when the phone trunk/provider uses the older SIP protocol.

sip_general.conf
Location:
/etc/release/interdialog/sip_general.conf

Change:
- localnet -> Set to the CentOS server's IP subnet.
  Example:
  192.168.201.0/255.255.254.0
- domain -> CentOS server's IP.
- register line -> Change the trunk number and trunk server IP.
- Trunk section [9017] -> Change host IP to the trunk provider's IP.

Key settings:
port=5060
- Standard SIP port.

bindaddr=0.0.0.0
- Listen on all network interfaces.

disallow=all / allow=all
- Block all codecs first, then allow all.

nat=force_rport
- Handle calls behind NAT/routers.

dtmfmode=info
- Send keypad tones through SIP INFO messages.

rtptimeout=30
- Hang up if no audio for 30 seconds.

maxexpiry=3600
- Maximum time of 1 hour that a SIP registration is valid.

callerid=LITE
- Name shown as caller ID.

qualify=yes
- Regularly ping the trunk to check if it is alive.

After editing:
asterisk -r

Then type:
reload

extensions.conf
Location:
/etc/release/interdialog/extensions.conf

This is the master dialplan file and points to other sub-files.

For SIP mode, uncomment:
#include extensions_general.conf
#include extensions_redirect.conf
#include extensions_outbound.conf

Comment out PJSIP lines:
;#include extensions_general_PJSIP.conf
;#include extensions_redirect_PJSIP.conf
;#include extensions_outbound_PJSIP.conf

In Asterisk configuration files, ; at the beginning of a line means the line is a comment and is ignored.

modules.conf — SIP mode instruction from the Asterisk installation/configuration training file:
noload = chan_pjsip.so
noload = res_pjsip.so
load = chan_sip.so

This instruction tells Asterisk not to load PJSIP modules and to load SIP.

extensions_general.conf
Location:
/etc/release/interdialog/extensions_general.conf

Change:
- TRUNK_GRP -> SIP trunk number, for example SIP/9017.
- HTTPPATH -> Server IP for the recordings URL.
- ACD_1 -> Server IP + port 5060.

Key settings:
TRUNK_GRP => SIP/9017
- Trunk used for calls.

HTTPPATH
- Web URL where call recordings are stored.

RECORDING_ENABLED => Y
- Turns on call recording.

RECORDING_PATH
- Folder where recordings are saved.

DBTYPE => MYSQL
- Database type: MySQL or SQL Server.

IVR_WAIT_TIMEOUT => 60
- Wait 60 seconds for IVR input before timing out.

MANUAL_DIAL_TIMEOUT => 90
- Wait 90 seconds for an agent's manual call.

INVALID_ATTEMPT => 3
- Allow 3 wrong IVR inputs before disconnecting.

WAIT_TIMEOUT => 30
- General wait timeout in seconds.

ACD_1 => IP:5060
- Address of the ACD call-routing server.

SHOWCLID => Y
- Show Caller ID.

After editing, reload the dialplan:
asterisk -rvvvvv

Then type:
dialplan reload

Apache Web Server for Asterisk Recordings

Purpose:
Make call recordings accessible through a web browser.

File:
/etc/httpd/conf/httpd.conf

Add at the end of the file:
ServerName 192.168.201.195

<Directory />
Options Indexes
AllowOverride all
Require all granted
</Directory>

<VirtualHost *:80>
Options Indexes
ServerPath /Recordings
DocumentRoot /home/Recordings
ServerName 192.168.201.195
</VirtualHost>

Change 192.168.201.195 to the server IP.

Key terms:
- ServerName: Server's IP address.
- VirtualHost *:80: A virtual website running on port 80 (HTTP).
- DocumentRoot: Folder on disk where recordings are stored.
- ServerPath /Recordings: URL path used to access recordings.

Start the web server:
service httpd start

Test in a browser:
http://192.168.201.195/Recordings/

The training notes state that a list of recording files should be visible.

Configuring Asterisk with PJSIP

Use PJSIP when the provider supports the newer PJSIP protocol.

Step 1 — modules.conf: switch to PJSIP
load = chan_pjsip.so
load = res_pjsip.so
noload = chan_sip.so

Step 2 — Reload modules in the Asterisk CLI:
asterisk -rvvvvv
module reload

Step 3 — extensions.conf: switch to PJSIP dialplan
Comment out SIP line:
;#include extensions_general.conf

Uncomment PJSIP line:
#include extensions_general_PJSIP.conf

Step 4 — extensions_general_PJSIP.conf
Use the PJSIP/ prefix:
TRUNK_GRP => PJSIP/9008
TRUNK_GRP_PJSIP => 9008

Step 5 — PJSIP_general.conf
This file defines how Asterisk connects to the trunk using PJSIP.

The training document states "PJSIP has 5 object types (sections) for each trunk" and lists:
- transport: How to send/receive SIP packets (UDP, port 5060).
- registration: How Asterisk registers itself to the trunk provider.
- auth: Username and password for authentication.
- aor (Address of Record): Contact address/location of the trunk.
- endpoint: Actual connection settings such as codec and context.
- identify: Matches incoming calls from the trunk's IP.

Example for trunk 9025:
- Registers at sip:9025@192.168.200.253
- Uses password ab1234
- Allows codec alaw
- Context set to outgoing for outbound calls.

Step 6 — Reload dialplan:
asterisk -rvvvvv
dialplan reload

SIP and PJSIP Comparison

SIP:
- Config file: sip_general.conf
- Module to load: chan_sip.so
- Dialplan files: extensions_general.conf
- Trunk prefix: SIP/9017
- Complexity: Simpler
- Recommended in the training notes: Older setups

PJSIP:
- Config file: PJSIP_general.conf
- Modules to load: chan_pjsip.so + res_pjsip.so
- Dialplan files: extensions_general_PJSIP.conf
- Trunk prefix: PJSIP/9008
- Complexity: More structured
- Recommended in the training notes: New/modern setups

Generating a Lock ID and Getting a Licence

A Lock ID is a unique hardware fingerprint of the machine based on the network adapter MAC address. The licence is locked to this ID.

Step 1.1
- Create a blank:
licence.lic
file in the CTIServer folder.
- Run:
CTIServer.exe

Step 1.2
- CTIServer generates:
IDG_LICENSE.LOG
- Open it in Notepad.
- Example:
Checking 0A357-AC3E2-383D2-0D0AA50- [Realtek PCIe...]
Unable to decrypt license file
- The code:
0A357-AC3E2...
is the Lock ID.

Step 1.3
- Email the Lock ID to the licensing team with required licence parameters.

Step 1.4
- Receive a .lic file by email.
- Example name:
TSPL DEL HD - Sonu_...lic

Step 1.5
- Rename the received file to:
licence.lic
- Place it in the CTIServer folder.

Step 1.6
- CTI Server can then start.

Dialler Types

Preview:
- Agent sees customer information first.
- Agent manually clicks to call.
- Full agent control.
- Used for complex/sensitive calls.
- Slowest speed.

Progressive:
- System auto-dials one number per available agent.
- No manual dialling required.
- Balanced speed and control.
- Described as the most common.

- Dials multiple numbers at once before agents are free.
- Uses algorithms to predict availability.
- Used for high-volume campaigns.
- Fastest.
- Requires pacing ratio.

Progressive (no IVR):
- Same as Progressive but skips the IVR/voice menu.
- Connects customer directly.
- Used when no IVR flow is needed.

Training rule:
Preview = most control
Progressive = balanced
Predictive = fastest volume

Pacing ratio applies only to the Predictive Dialler. It controls how aggressively the system dials ahead of available agents.

More calls are dialled and there is a higher risk of abandoned calls if agents are busy.

Lower ratio:
Fewer abandoned calls, but agents may be idle between calls.

ID CLOUD OUTBOUND DIAL ORDER AND LCR

Terminology

Phone Dialorder:
Default sequence ID Cloud follows to dial a lead's multiple contact numbers. The default dialorder supports at least 15 customer contact numbers per lead.

Advance Phone Dialorder:
A custom dialorder created by the admin with its own name, slot sequence, and time range. It can be attached to a service instead of the default dialorder.

Timebased Phone Dialorder:
Dialorder where the phone number selected depends on the time of day. The number of phone numbers per lead and the time range can be configured.

LCR (Least Cost Routing):
Routing method that sends outbound calls through the carrier/route that is fixed or cheapest for a given area/zip code.

Carrier:
A telecom vendor/trunk added under Master and used as a route for outbound calls.

MSC Code (Master Switching Code):
A routing rule linking:
- Carrier
- Zip code
- CLI start index
- CLI length

Fixed Port:
A specific IVR port, for example IVR1-1, permanently tied to one carrier.

Outbound MSC Code:
The MSC code selected at the service/campaign level so outbound calls from that service follow the chosen routing rule.

Disk Partitioning

Partitioning means dividing a hard disk into different sections so that the operating system and user data can be managed efficiently.

Reasons for partitioning:
- Better data organization
- Easy backup
- Improved performance
- Easier recovery if OS crashes

/boot
Purpose: Stores boot files required to start Linux.
Recommended Size: 2 GB
Contents:
- Linux Kernel
- Boot Loader (GRUB)

Swap Partition
Purpose: Acts as Virtual RAM when physical RAM becomes full.
Rule:
Swap Size = 2 × RAM

Examples:

- 8 GB RAM -> 16 GB Swap

/home
Purpose: Stores user files.
Examples:
- Documents
- Downloads
- Videos
- Recordings
- Desktop Files
Recommended: 10 GB or more depending on usage.

Root Partition (/)
Purpose: Stores:
- Linux Operating System
- Installed Software
- System Files
- Configuration Files
Recommended Size: Minimum 150 GB (for 1 TB HDD)

Final Partition Layout:
- /boot | 2 GB | Boot Files
- Swap | 2 × RAM | Virtual Memory
- /home | 10 GB or more | User Data
- / | 150 GB or more | Operating System

ASTERISK

Asterisk and Telephony Terminology

Asterisk:
A free, open-source PBX (Private Branch Exchange) software that manages phone calls, voicemail, conference calls, and more. It acts as the telephony server that handles SIP/PJSIP calls. The CTI application connects to Asterisk to manage agent calls.

CentOS:
A free Linux operating system where Asterisk is installed.

RPM:
A software package format for Linux, similar to an .exe installer for Windows.

WinSCP:
A Windows tool to transfer files to/from a Linux server over the network.

PuTTY:
A Windows tool used to type commands into a Linux server remotely.

SIP (Session Initiation Protocol):
A signaling protocol used for initiating, maintaining, and terminating real-time communication sessions such as voice calls, video calls, and messaging. SIP peers such as phones and trunks register with Asterisk.

PJSIP:
A newer, more feature-rich SIP library/channel driver in Asterisk that replaces the older chan_sip. It supports features such as WebRTC, IPv6, and better TLS handling.

Trunk:
The connection between the Asterisk server and the phone network.

Dialplan:
The set of rules that determines what Asterisk does when a call comes in or goes out, including routing calls to agents, queues, voicemail, and IVRs.

ACD / ACD Port:
ACD means Automatic Call Distributor / Automatic Call Distribution. It routes incoming calls to the right agent or queue. The ACD Port is the configuration point in the CTI web console that tells the system which Asterisk server to connect to for call routing.

IVR:
Interactive Voice Response, such as a "Press 1 for Sales, Press 2 for Support" menu.

CLI:
Command Line Interface, the text-based interface where commands are entered.

Codec (alaw):
The format used to encode voice audio. alaw is commonly used in India/Europe.

DTMF:
Dual-Tone Multi-Frequency, the tones generated when phone number keys are pressed.

NAT:
Network Address Translation, used when calls pass through routers/firewalls.

CDR:
Call Detail Records, logs of calls including who called, when, and duration.

Httpd:
Apache web server, used here to make call recordings accessible through a browser.

CTI (Computer Telephony Integration):
Technology that allows computers and telephone systems to interact. Interdialog connects to Asterisk to control and supervise calls. CTI can link Asterisk call events with an agent's computer screen for functions such as screen pop-ups and call logging.

AMI (Asterisk Manager Interface):
A management protocol/interface that allows external applications to communicate with Asterisk to control calls, monitor events, and manage the PBX programmatically. The CTI application uses AMI through manager.conf to authenticate and receive real-time call events.

Configuring Asterisk with SIP

Use SIP when the phone trunk/provider uses the older SIP protocol.

sip_general.conf
Location:
/etc/release/interdialog/sip_general.conf

Change:
- localnet -> Set to the CentOS server's IP subnet.
  Example:
  192.168.201.0/255.255.254.0
- domain -> CentOS server's IP.
- register line -> Change the trunk number and trunk server IP.
- Trunk section [9017] -> Change host IP to the trunk provider's IP.

Key settings:
port=5060
- Standard SIP port.

bindaddr=0.0.0.0
- Listen on all network interfaces.

disallow=all / allow=all
- Block all codecs first, then allow all.

nat=force_rport
- Handle calls behind NAT/routers.

dtmfmode=info
- Send keypad tones through SIP INFO messages.

rtptimeout=30
- Hang up if no audio for 30 seconds.

maxexpiry=3600
- Maximum time of 1 hour that a SIP registration is valid.

callerid=LITE
- Name shown as caller ID.

qualify=yes
- Regularly ping the trunk to check if it is alive.

After editing:
asterisk -r

Then type:
reload

extensions.conf
Location:
/etc/release/interdialog/extensions.conf

This is the master dialplan file and points to other sub-files.

For SIP mode, uncomment:
#include extensions_general.conf
#include extensions_redirect.conf
#include extensions_outbound.conf

Comment out PJSIP lines:
;#include extensions_general_PJSIP.conf
;#include extensions_redirect_PJSIP.conf
;#include extensions_outbound_PJSIP.conf

In Asterisk configuration files, ; at the beginning of a line means the line is a comment and is ignored.

modules.conf — SIP mode instruction from the Asterisk installation/configuration training file:
noload = chan_pjsip.so
noload = res_pjsip.so
load = chan_sip.so

This instruction tells Asterisk not to load PJSIP modules and to load SIP.

extensions_general.conf
Location:
/etc/release/interdialog/extensions_general.conf

Change:
- TRUNK_GRP -> SIP trunk number, for example SIP/9017.
- HTTPPATH -> Server IP for the recordings URL.
- ACD_1 -> Server IP + port 5060.

Key settings:
TRUNK_GRP => SIP/9017
- Trunk used for calls.

HTTPPATH
- Web URL where call recordings are stored.

RECORDING_ENABLED => Y
- Turns on call recording.

RECORDING_PATH
- Folder where recordings are saved.

DBTYPE => MYSQL
- Database type: MySQL or SQL Server.

IVR_WAIT_TIMEOUT => 60
- Wait 60 seconds for IVR input before timing out.

MANUAL_DIAL_TIMEOUT => 90
- Wait 90 seconds for an agent's manual call.

INVALID_ATTEMPT => 3
- Allow 3 wrong IVR inputs before disconnecting.

WAIT_TIMEOUT => 30
- General wait timeout in seconds.

ACD_1 => IP:5060
- Address of the ACD call-routing server.

SHOWCLID => Y
- Show Caller ID.

asterisk -rvvvvv

Then type:
dialplan reload

Configuring Asterisk with PJSIP

Use PJSIP when the provider supports the newer PJSIP protocol.

Step 1 — modules.conf: switch to PJSIP

This file defines how Asterisk connects to the trunk using PJSIP.

The training document states "PJSIP has 5 object types (sections) for each trunk" and lists:

- Allows codec alaw

Dialler Types

Preview:
- Agent sees customer information first.
- Agent manually clicks to call.
- Full agent control.
- Used for complex/sensitive calls.
- Slowest speed.

Progressive:
- System auto-dials one number per available agent.
- No manual dialling required.
- Balanced speed and control.
- Described as the most common.

Predictive:
- Dials multiple numbers at once before agents are free.
- Uses algorithms to predict availability.
- Used for high-volume campaigns.
- Fastest.
- Requires pacing ratio.

Progressive (no IVR):
- Same as Progressive but skips the IVR/voice menu.
- Connects customer directly.
- Used when no IVR flow is needed.

Training rule:
Preview = most control
Progressive = balanced
Predictive = fastest volume

Customer hears a message and must press 1 to reach an agent.

Pacing Ratio and Module-wise Pacing

Pacing ratio applies only to the Predictive Dialler. It controls how aggressively the system dials ahead of available agents.

Pacing ratio = 2:
For every 1 available agent, the system dials 2 numbers simultaneously.

Higher ratio:
More calls are dialled and there is a higher risk of abandoned calls if agents are busy.

Lower ratio:
Fewer abandoned calls, but agents may be idle between calls.

ID CLOUD OUTBOUND DIAL ORDER AND LCR

Terminology

Phone Dialorder:
Default sequence ID Cloud follows to dial a lead's multiple contact numbers. The default dialorder supports at least 15 customer contact numbers per lead.

Advance Phone Dialorder:
A custom dialorder created by the admin with its own name, slot sequence, and time range. It can be attached to a service instead of the default dialorder.

Timebased Phone Dialorder:
Dialorder where the phone number selected depends on the time of day. The number of phone numbers per lead and the time range can be configured.

LCR (Least Cost Routing):
Routing method that sends outbound calls through the carrier/route that is fixed or cheapest for a given area/zip code.

Carrier:
A telecom vendor/trunk added under Master and used as a route for outbound calls.

MSC Code (Master Switching Code):
A routing rule linking:
- Carrier
- Zip code
- CLI start index
- CLI length

Fixed Port:
A specific IVR port, for example IVR1-1, permanently tied to one carrier.

Outbound MSC Code:
The MSC code selected at the service/campaign level so outbound calls from that service follow the chosen routing rule.

ID CLOUD VIASMS GATEWAY SETUP

Terminology

SMS Gateway:
A system/service that allows ID Cloud to send and receive SMS messages such as OTPs, alerts, and notifications through a telecom SMS aggregator.

ViaSMS Gateway:
The SMS channel module inside:
Master > SMS Channel
used to configure and connect an external SMS gateway provider.

SMPP (Short Message Peer-to-Peer):
Industry-standard protocol used for exchanging SMS messages between ID Cloud and the SMS gateway provider. It is selected as the Type while configuring the SMS channel.

Configuration Data (IP Address of Gateway):
The connection endpoint/IP address of the SMS gateway vendor that ID Cloud connects to through SMPP.

smsgateway Application:
A background service/application that must be running on the server for SMS to send/receive. Configuration alone is not enough.

OTP (One-Time Password):
An auto-generated, time-bound numeric code sent through SMS to the agent's registered mobile number for Forgot Password / agent login verification.

viasms_queue:
Backend database table where outgoing/incoming SMS messages are logged. It is used to verify whether a message such as an OTP was generated and queued by the system.

ViaSMS Gateway Setup

Step 1:
Navigate to:
Master > SMS Channel > Add

Step 2:
Enter channel Name.
Set:
Enable = Yes
Type = SMPP
Set Start Time and End Time for the active window.

Step 3:
Enter Configuration Data:
- IP Address of the SMS Gateway vendor.

Step 4:
Click Update, then Continue.

Step 5:
Start the:
smsgateway
application on the server.

Step 6:
Test through Agent Login:
- Agent clicks Forgot Password.
- System asks for registered mobile number.
- Agent enters mobile number.
- Click Next.

Step 7:
OTP should be received on the agent's mobile number.

Step 8 — Troubleshooting if OTP is not received:
- Check the:
viasms_queue
table.
- A message entry should appear if the system generated it.
- The training material uses this to distinguish:
  - Application-side issue: message not queued.
  - Gateway/vendor-side issue: message queued but not delivered.

Requirement-Gathering Points for SMS Gateway

Confirm:
1. Which SMS gateway vendor is used, because this affects SMPP configuration/IP.
2. Whether OTP-based login is mandatory or optional for agents.
3. Expected SMS volume.
4. Compliance requirements around SMS content, for example DLT registration in India for BFSI clients.

SMS/OTP Troubleshooting Checkpoint

If SMS/OTP is not received during a demo or UAT, the training material identifies viasms_queue as the first checkpoint to determine whether the issue is on the ID Cloud side or gateway/vendor side.

Intervals: Specify the pattern as one of the below:
Interval Based: Calls are retried after a certain interval. E.g. A retry pattern given as (30,30,30,0) implies that after a 30-minute interval, all calls with this disposition will be added to the dialling queue and each call will be tried for a maximum of three times and then will be closed.
Time Based: Calls are retried based on time. Egg. A retry pattern given as (090012001830.0, 120018000900.1) implies that all calls that were dialled and not contacted between 9:00 AM to 12 PM will be added to the dialling queue at 6:30 PM. Similarly, calls dialled and not contacted between 12:00 PM to 6:00 PM will be added to the dialling queue at 9:00 AM the next day.

Removes (deletes) files or directories. When used with directories, the -r (recursive) option is required.
Example: rm file.txt (deletes "file.txt"), rm -r old_folder (deletes "old_folder" and its contents)

Copies files or directories from a source to a destination. The -r option is needed for copying directories.
Example: cp source.txt destination.txt (copies "source.txt" to "destination.txt"), cp -r folder1 folder2 (copies "folder1" and its contents to "folder2")
mv:
Moves or renames files or directories.

top:
Monitors and sorts processes based on CPU utilization, memory usage, and other metrics, providing a dynamic view of system activity.
